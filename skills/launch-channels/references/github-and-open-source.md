# GitHub and open source

For developer tools and open-source projects the repository is the landing page.

## The README is the launch page

- First screen: what it is in one sentence, a GIF or screenshot of it working, and
  the one command or link to try it.
- Then: why it exists (the problem), install, a minimal example, how it compares
  to the obvious alternatives (fairly), license, how to contribute.
- Badges only if they mean something (tests, version, license).

## Make it look alive

- A tagged release with notes for the launch version.
- Topics set on the repository so it shows up in GitHub's topic pages.
- A few "good first issue" issues and a CONTRIBUTING.md if you want contributors.
- Answer issues and pull requests fast during launch week - first visitors watch
  how maintainers respond.

## Where developers find projects

- Show HN (see hacker-news.md).
- Curated "awesome" lists for the field: open a pull request that follows the
  list's own contribution rules.
- Reddit's subreddits for the language or field; dev.to or a blog post explaining
  how it works.
- Package registries (npm, PyPI): a clear description and keywords.

Never ask for stars in exchange for anything, and never buy them.
